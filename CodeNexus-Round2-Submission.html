2.What We Built in Round 2

We built the core governance loop end to end: guidelines go in, content is checked against them, each issue is explained and tied to the exact rule it breaks, and a human approves or rejects. A judge can open the link and run the full workflow with no walkthrough.

The central workflow, working: paste or upload guidelines → submit content → Aegis returns cited, explainable flags with suggested fixes → apply fixes and re-check → a reviewer records the final Approve / Reject decision → download a governance report.

The explainability guarantee (the part we care about most)

Every flag must quote a rule that literally appears in the guidelines you supplied. After the AI responds, the server drops any flag whose quoted rule is not actually found in the submitted guidelines. If nothing approved backs a flag, it is not shown. This is what makes the output trustworthy to a compliance reviewer rather than a generic "the AI thinks this is wrong".

OCR endpoint/api/ocrAccepts one rendered page image and returns its transcribed text.

State & hostingIn-session React state · VercelNo database and no sign-in for the demo, so any judge can open the link and use it immediately.
How the explainability is enforced in code. The model is asked to return, for every issue, the rule text copied word-for-word from the guidelines. The server then normalises whitespace and quotes and checks that the quoted rule is a real substring of the submitted guidelines. Flags that fail this check are discarded and counted separately as "uncited flags dropped". The result is that a flag can always be traced back to an approved rule.

5.Changes From the Original Plan

We kept the product idea and the core workflow exactly as proposed. The changes below were made to deliver a reliable, openable demo in the Round 2 window, and each was a deliberate scoping decision.

ArchitectureReact/Next.js frontend + separate FastAPI backendOne Next.js app with API routes. Fewer moving parts, a single deploy, and no second service to keep running during judging.
AI providerInkloom AI creditsGoogle Gemini free tier — the API we had a working key for, so the demo does not depend on credits we would only receive later.

Scope added—Scanned-PDF OCR was added because real brand guidelines often live in PDFs, including scanned ones.

6.Three Major Improvements for Round 3

Each of these is a meaningful addition to the product, not a cosmetic change.

1 · Retrieval + persistence

Add a vector store so guidelines larger than the model's context window can still be cited precisely, and a database for saved content, version history, team roles and a full audit log — turning the demo into a system teams return to over time.

2 · Image & accessibility checks

Extend review to visual content: logo-variant and brand-colour checks, colour-contrast and alt-text accessibility checks — so Aegis governs images and not only text.

3 · Governance analytics

Track which guidelines get flagged again and again to surface the rules that are unclear or contradictory. Aegis would then improve the brand book itself, not just check content against it.

7.How to Run & Review

  1. Open the working-project link (above) in a browser.
  2. Press Load example to fill sample guidelines and an off-brand draft — or paste/upload your own.
  3. Press Run governance check. Each issue appears with the rule it breaks, the offending text, and a suggested fix.
  4. Use Apply fix or Fix all, then Re-run check to watch the issues clear.
  5. Accept or dismiss flags, record the final Approve / Reject decision, and Download report.
